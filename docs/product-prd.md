# 产品方案（PRD）

## 1. 产品定位

体检报告解读系统面向三类核心用户：

- 普通体检用户：看不懂报告，希望知道“有没有问题、严重不严重、下一步做什么”
- 慢病风险人群：更关注长期趋势与个性化阈值，而不是单次是否超标
- 医生/家属协作方：需要快速查看摘要、重点异常和依据来源

产品核心价值不是“复述报告”，而是把分散、难懂、格式不一的体检结果，转成一套可理解、可追踪、可行动的健康洞察系统。

## 2. 目标与成功标准

### 2.1 业务目标

- 提升体检报告解读完成率和用户停留时长
- 提升异常指标点击率、建议采纳率与复查转化率
- 建立可信专业感，提升用户复用与多次上传率

### 2.2 用户目标

- 5 秒内了解整体状况
- 30 秒内识别本次最该关注的异常项
- 2 分钟内获得一份可执行的个人行动建议

### 2.3 产品指标

- 报告解析成功率 >= 95%
- 指标标准化映射准确率 >= 98%
- 异常识别准确率 >= 99%（基于规则层）
- 重点异常点击率 >= 60%
- 历史报告复传率 >= 35%

## 3. 用户核心问题

### 3.1 当前痛点

- 体检报告格式杂乱，不同医院差异大
- 专业术语难懂，看见箭头也不知道是否严重
- 不清楚“实验室异常”和“临床风险”是否是一回事
- 看不到趋势，只能盯着单次结果
- 建议常常泛泛而谈，无法转化为行动

### 3.2 设计原则

- 重点优先：只先呈现最该关注的问题
- 分层解释：白话层、个性化层、专业层逐层展开
- 依据透明：所有结论可追溯到指南、规则或阈值版本
- 个体化：年龄、性别、既往史、家族史影响解读必须可见
- 趋势优先：持续恶化即使未超标，也应成为独立提醒

## 4. 核心功能模块

### 4.1 报告解析引擎

#### 功能范围

- 支持图片、扫描件、PDF 上传
- OCR 文本识别
- 表格检测与结构化抽取
- 医院模板识别与字段映射
- 指标标准化与单位归一化

#### 输出目标

将非结构化报告转成统一指标对象：

- 指标编码
- 中文名/别名
- 原始值
- 单位
- 实验室参考范围
- 报告时间
- 检验机构
- 原文定位信息

### 4.2 智能解读与风险评估

#### 功能范围

- 正常 / 偏高 / 偏低 / 危急 分级
- 个性化阈值修正
- 临床风险阈值与实验室参考值分离展示
- 综合风险评分生成
- 异常指标排序

#### 解读要求

每个异常项都必须输出：

- 本次结果是什么
- 为什么会提示异常
- 可能意味着什么
- 严重程度
- 建议下一步做什么
- 依据来自哪里

### 4.3 趋势追踪与纵向对比

#### 功能范围

- 多次报告归档
- 同指标跨时间绘图
- 趋势性恶化识别
- 边界值长期上升识别
- 本次与历史最好/最差结果比较

#### 典型场景

- 空腹血糖连续 3 次上升但未超标
- 甘油三酯本次恢复正常，但半年内波动显著
- ALT 单次轻度升高，但历史上长期稳定，需要降低优先级

### 4.4 自然语言解释层

#### 三层语言架构

第一层：默认白话摘要
- 用用户听得懂的话说明“发生了什么”和“意味着什么”

第二层：个性化解释
- 结合用户年龄、性别、BMI、家族史、既往史补充“对你意味着什么”

第三层：专业细节
- 展示原始术语、阈值依据、指南来源、趋势计算逻辑、专业说明

### 4.5 干预建议引擎

#### 功能范围

- 单指标建议
- 指标组合建议
- 生活方式建议
- 复查周期建议
- 就医优先级建议
- 红旗风险快速转诊建议

#### 建议输出形式

- 优先做什么
- 为什么优先
- 建议在多久内完成
- 是否需要复查或就医
- 哪类科室更合适

### 4.6 报告管理与导出

#### 功能范围

- 用户档案
- 历史报告云端存储
- 健康摘要卡生成
- PDF 导出
- 一键分享给医生/家人

## 5. 页面与交互设计

### 5.1 第一屏：健康总览仪表盘

目标：5 秒内形成整体认知

页面元素：

- 综合健康评分，如 82/100
- 风险颜色环
- 按系统分组的健康模块
  - 心血管
  - 肝功能
  - 血糖代谢
  - 肾功能
  - 血常规
- 顶部重点提醒
  - 本次最高优先级问题
  - 趋势性风险提示
  - 是否存在需要尽快复查项

### 5.2 第二屏：异常指标详情

目标：只展示值得关注的内容

卡片字段：

- 指标名称
- 本次结果
- 实验室参考范围
- 临床风险阈值
- 通俗解释
- 影响程度
- 个性化修正说明
- 趋势信号
- 建议行动
- 依据来源

### 5.3 第三屏：个性化行动建议

目标：把洞察转成清晰行动

行动卡片结构：

- 优先级：高 / 中 / 低
- 动作：复查 / 就医 / 饮食调整 / 运动管理 / 观察随访
- 时间建议：立即、1 周内、1 个月内、3 个月内
- 触发依据：本次异常 / 趋势恶化 / 既往史叠加

## 6. 重点突出机制

系统需要建立异常排序引擎，优先级不由“是否超标”单独决定，而由以下四个维度联合决定：

- 偏离程度：距离正常范围或临床阈值多远
- 临床重要性：该指标对实际风险的临床意义
- 趋势强度：是否持续恶化、波动异常、边界上升
- 个体基础风险：年龄、性别、家族史、慢病背景

### 示例排序公式

```text
priority_score = deviation_score
               * clinical_weight
               * trend_weight
               * personal_risk_weight
```

## 7. 可信度设计

### 四条铁律

- 指南版本必须明确标注
- 实验室正常范围与临床风险阈值必须分开显示
- 趋势异常需要独立提示，不依赖本次是否超标
- 个性化阈值修正必须透明说明原因

## 8. 非功能要求

- 数据安全：符合医疗数据隐私保护要求
- 可追溯性：关键结论具备规则链路和来源记录
- 可扩展性：支持新增医院模板、指标字典和知识库接入
- 可靠性：规则判定与 LLM 文本生成解耦，确保底层判断稳定

## 9. 分期路线图

### Phase 1：MVP（6-8 周）

- 用户注册与健康档案
- PDF/图片上传
- OCR + 表格抽取
- 指标标准化
- 单次报告解读
- 第一屏总览 + 第二屏异常项卡片
- PDF 摘要导出

### Phase 2：增强版（8-12 周）

- 多次报告管理
- 趋势曲线与纵向对比
- 个性化阈值修正
- 综合风险评分
- 依据来源展示

### Phase 3：智能增强（12 周+）

- 对话式追问
- 外部知识库接入
- 医生协作链接
- 高风险转诊与保险/健康管理服务联动
