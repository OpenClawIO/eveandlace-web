# 技术架构

## 1. 架构总览

建议采用“规则引擎为主、模型增强为辅”的分层架构，避免把医学安全决策完全交给大模型。

```text
客户端
  -> API 网关
    -> 身份与用户档案服务
    -> 报告解析服务
    -> 指标标准化服务
    -> 规则与评分服务
    -> 趋势分析服务
    -> 解读生成服务
    -> 建议引擎服务
    -> 报告管理与导出服务
    -> 知识库与依据服务
```

## 2. 服务拆分

### 2.1 Web / H5 客户端

职责：

- 上传报告
- 查看总览、异常详情、趋势图、行动建议
- 管理用户档案
- 发起导出与分享

推荐技术：

- Next.js 或 React + TypeScript
- ECharts / Recharts 绘制趋势图
- TanStack Query 管理数据请求

### 2.2 API 网关

职责：

- 鉴权
- 聚合查询
- 请求路由
- 限流与审计日志

### 2.3 报告解析服务

职责：

- 文件预处理
- OCR 调用
- 表格区域检测
- PDF 文本抽取
- 模板识别
- 原始字段抽取

建议能力组合：

- OCR：PaddleOCR / 云 OCR
- PDF：pdfplumber / PyMuPDF
- 表格提取：Camelot / Tabula / 自研版面分析

### 2.4 指标标准化服务

职责：

- 医院字段别名映射
- 单位换算
- 指标编码归一
- 系统分组归类
- 参考范围标准化存储

关键输出：统一的 `LabMetric` 领域对象。

### 2.5 规则与评分服务

职责：

- 实验室参考范围判定
- 临床风险阈值判定
- 危急值识别
- 个性化阈值修正
- 优先级评分
- 综合健康评分

设计原则：

- 全部核心判定规则配置化
- 每次判定保留规则命中链路
- 输出 machine-readable 结果，供前端和解释层复用

### 2.6 趋势分析服务

职责：

- 同指标时间序列聚合
- 同单位归一
- 趋势恶化检测
- 波动性分析
- 边界上升识别

### 2.7 解读生成服务

职责：

- 把规则结果转成三层文本
- 输出白话解释、个性化解释、专业依据说明
- 支持用户追问

设计方式：

- 模板 + LLM 混合生成
- 结论结构先由规则产出，再交给模型润色
- 所有模型输出必须带来源锚点，禁止凭空生成医学依据

### 2.8 建议引擎服务

职责：

- 把异常单项与组合模式映射为建议
- 按优先级排序行动项
- 区分生活方式建议、复查建议、就医建议

### 2.9 知识库与依据服务

职责：

- 存储指南版本、章节、页码、证据等级
- 管理实验室参考范围与临床阈值
- 管理规则版本
- 支持外部知识库连接

## 3. 推荐数据流

### 3.1 上传解析链路

1. 用户上传 PDF / 图片
2. 文件服务完成存储与任务排队
3. 报告解析服务执行 OCR / PDF 抽取 / 表格识别
4. 指标标准化服务生成统一指标列表
5. 规则服务执行异常判定与评分
6. 趋势服务结合历史数据计算趋势信号
7. 解读服务生成三层说明
8. 建议引擎生成行动清单
9. 前端展示三层页面

### 3.2 用户追问链路

1. 用户点击某个异常项并追问
2. 系统拉取该指标的结构化结果、规则命中、知识依据
3. LLM 在受控上下文中回答“为什么异常、影响什么、为何这样建议”
4. 前端显示回答并标注依据来源

## 4. 核心表与存储设计

### 4.1 事务型数据库

适合存储：

- 用户档案
- 报告元数据
- 结构化指标
- 风险结果
- 规则版本
- 指南来源

建议：PostgreSQL

### 4.2 对象存储

适合存储：

- 原始 PDF / 图片
- 导出摘要 PDF
- OCR 中间产物

### 4.3 搜索 / 向量层

适合存储：

- 指南切片
- 医学知识条目
- 解释层检索增强语料

建议：OpenSearch / pgvector

## 5. 关键领域边界

### 5.1 规则层与生成层严格分离

规则层负责：

- 数值判定
- 风险分级
- 阈值修正
- 趋势计算
- 优先级排序

生成层负责：

- 通俗表达
- 上下文组织
- 追问交互

### 5.2 医学依据与展示逻辑分离

- 指南、阈值、证据等级独立建模
- 前端只消费结构化依据，不直接拼接原始文本

## 6. 安全与合规

- 上传文件加密存储
- 传输链路全程 HTTPS
- 关键字段脱敏
- 用户授权后方可分享报告摘要
- 所有自动判定留审计日志
- 对高风险或危急值必须弹出免责声明与建议线下就医

## 7. 可观测性与质量控制

### 7.1 监控指标

- OCR 成功率
- 模板命中率
- 指标抽取准确率
- 单位换算异常率
- 规则判定冲突率
- LLM 引用缺失率

### 7.2 人工质检入口

建议保留运营/医学审核后台：

- 查看解析结果与原始定位
- 修正模板映射
- 回灌规则与知识库
- 抽检高风险案例

## 8. 推荐迭代策略

第一阶段优先覆盖高频指标与高价值系统：

- 血脂
- 血糖
- 肝功能
- 肾功能
- 血常规

第二阶段再逐步拓展：

- 肿瘤标志物
- 甲状腺
- 尿检
- 心电图/影像类非结构化结论
